# 税务口径假设清单

本工具的所有口径都是 `config/default.toml` 中的配置项。下面列出默认值及依据：
- **【用户已确认】**：用户本人确认的口径（2026-10-21）；
- **【待确认】**：按用户要求给出的默认方案，需用户最终确认；
- **【公开资料核实】**：已查到官方文本，出处见第 3 节；
- **【需确认】**：尚未确认，正式结算前请财务确认。

> 说明：本文档只陈述计算口径，不构成税务意见。

## 1. 计算流程（默认口径）

```
企业总成本 C（精确到分，任意 C ≥ 0 都完整拆分，三项之和恒等于 C）
  ├─ C < 1000：不征收。不含税收入 N = C，增值税 V = 0，附加税 S = 0
  ├─ C ≥ 1000：征收（含门槛跳变段，见 G5）
  │    估算收入 E = C / (1 + 1% × (1 + 3%))
  │    增值税 V = round(E × 1%)，附加税 S = round(V × 3%)
  │    不含税收入 N = C − V − S（倒挤）
  │    自洽校验：round(N × 1%) 应等于 V；不等时在 V ± 0.01 内找自洽组合，找不到按倒挤结果
  ├─ 个税（居民个人劳务报酬预扣预缴，按不含税收入 N）：
  │    减除费用 D = N ≤ 4000 ? 800（N < 800 时以 N 为限）: round(N × 20%)
  │    应纳税所得额 T = N − D
  │    代扣个税 I = round(T × 预扣率 − 速算扣除数)（预扣率表二）
  └─ 实际到手 = N − I（附加税不从到手扣）
```

round = 四舍五入到分（MidpointAwayFromZero），每一步单独舍入。

## 2. 逐条口径

| 编号 | 配置项 | 默认值 | 说明 | 状态 |
|---|---|---|---|---|
| A1 | `cost.basis` | `vat_and_surcharge_inclusive` | 企业总成本 = 不含税收入 + 增值税 + 附加税，三项都由企业承担。可选 `vat_inclusive`：总成本 = 价税合计（价税分离、增值税倒挤）。 | **【用户已确认】** |
| A2 | （固定逻辑） | — | **不出现未分配差额**：任意总成本（精确到分）都完整拆分为三项，三项相加正好等于总成本。 | **【用户已确认】** |
| A3 | `cost.consistent_search` | `true` | **拆分方法**：估算收入 = 总成本 ÷ (1 + 1% × (1 + 3%))；增值税 = round(估算收入 × 1%)；附加税 = round(增值税 × 3%)；不含税收入 = 总成本 − 增值税 − 附加税（倒挤）。倒挤收入再算增值税若与原值不等，在增值税 ±0.01 范围内找一个自洽组合（收入 × 1% 舍入后等于增值税、增值税 × 3% 舍入后等于附加税），找不到才按倒挤结果。逐分舍入使一部分总成本根本不存在自洽组合（经统计约 1% 的应征收总成本，如 1000.70 → 收入 990.50、增值税 9.90，而 990.50 × 1% = 9.905 舍入为 9.91），这时增值税与“收入 × 1%”差 0.01。设为 `false` 则直接按倒挤结果，不做相邻搜索。 | **【待确认】** |
| T1 | `take_home.deduct_surcharge` | `false` | 实际到手 = 不含税收入 − 代扣个税；附加税由企业承担，不从到手扣。 | **【用户已确认】** |
| V1 | `vat.rate` | `0.01` | 增值税 = 不含税收入 × 1%。 | **【用户已确认】** |
| S1 | `surcharge.base` / `surcharge.items` | `vat` / 单项 3% | 附加税 = 增值税额 × 3%（一个合计税率）。如需拆成城建税、教育费附加、地方教育附加，可改成多个税目。 | **【用户已确认】** |
| S2 | `surcharge.halve` | `false` | 不另做减半。 | **【用户已确认】**（3% 即最终税率） |
| G1 | `vat.threshold_enabled` / `threshold` | `true` / `1000` | **征收门槛**：不含税收入 ≥ 1000 元才征收增值税和附加税，低于 1000 元两者都为 0。这是**用户指定的业务口径**，与公开政策中的增值税起征点（如按次纳税的 300～500 元、按月 10 万元等）**不是同一回事**；本工具没有内置任何法定起征点。 | **【用户已确认】** |
| G2 | `vat.threshold_basis` | `net_revenue` | 门槛用不含税收入判断，不用总成本。可选 `total_cost`。 | **【用户已确认】** |
| G3 | `vat.levy_at_threshold` | `true` | 不含税收入恰好等于 1000 元时征收（“≥ 1000”含本数）；设为 `false` 则“> 1000”才征收。 | **【用户已确认】** |
| G4 | （固定逻辑） | — | 门槛只影响增值税和附加税；**个税不受此门槛影响**，始终按第 3 节的个税规则计算。 | **【用户已确认】** |
| G5 | `vat.threshold_gap` | `levy` | **门槛跳变段**：总成本 1000.00～1010.29 时，按不征收处理收入 = 总成本 ≥ 1000，与“收入 ≥ 1000 才征收”矛盾；按征收处理，倒挤收入又小于 1000（如 1000.00 → 989.80）。默认 `levy`：只要总成本 ≥ 1000（即不征收时收入就会达到门槛）就征收增值税和附加税，收入用倒挤结果，可能略低于 1000。理由：宁可略多缴，比少缴的合规风险小。可选 `exempt`：跳变段按不征收处理，收入 = 总成本，增值税、附加税为 0（收入超过 1000 却未征收）。 | **【待确认】** |
| P1 | `iit.income_base` | `net_revenue` | 个税的“每次收入”取不含税收入。可选 `total_cost`。 | 用户指定默认值 |
| P2 | `iit.deduct_surcharge` | `false` | 计算个税时不从收入中扣附加税（附加税由企业承担）。 | 随 T1 |
| P3 | `iit.fixed_deduction_limit` / `fixed_deduction` / `percent_deduction_rate` | 4000 / 800 / 20% | 每次收入不超过 4000 元减除 800 元；超过 4000 元减除 20%。 | **【公开资料核实】** |
| P4 | `iit.brackets` | 表二三档 | 预扣预缴应纳税所得额 ≤ 20000：20%、速算扣除数 0；20000～50000：30%、2000；> 50000：40%、7000。上限含本数。 | **【公开资料核实】** |
| P5 | （由公式推导） | — | 收入 ≤ 800 元时减除费用 800 元后余额为 0，个税为 0。公告没有单独写“800 元以下免税”，这是由“减除费用按八百元计算”推出来的。收入不足 800 元时，工具显示的减除费用等于收入本身，结果相同。 | 由核实规则推导 |
| P6 | （固定逻辑） | — | 按居民个人预扣预缴计算（预扣率表二）。非居民个人的劳务报酬适用税率表三、收入额按减除 20% 计算，本工具未实现。 | **【需确认】** 是否有非居民个人 |
| P7 | （固定逻辑） | — | **不考虑按月合并，每笔单独计算**：每行/每笔按“一次”独立计算，不做按人按月合并（公告第十一条关于“同一项目连续性收入以一个月内取得的收入为一次”的规定，本工具不处理）。 | **【用户已确认】** |
| R1 | `rounding.scale` / `rounding.mode` | 2 / `half_up` | 每一步金额四舍五入到分：增值税、附加税（逐项）、20% 减除费用、代扣个税。 | **【需确认】** 是否与开票/申报系统一致 |
| R2 | `reverse.prefer` | `min_cost` | 多个总成本得到同一到手时取最小总成本。 | 沿用 |
| R3 | `reverse.search_window` | 20 | 二分定位后前后各逐分扫描 20 分做校准。 | 实现参数 |
| R4 | `reverse.max_cost` | 100 亿 | 反算搜索上限。 | 实现参数 |

## 3. 个税规则的公开出处（只列实际查到的内容）

1. **国家税务总局公告 2018 年第 61 号**《国家税务总局关于发布〈个人所得税扣缴申报管理办法（试行）〉的公告》，2018-12-21 发布，2019-01-01 起施行。
   - 国家税务总局网站：<https://www.chinatax.gov.cn/n810219/n810744/n3752930/n3752974/c3963396/content.html>（正文；附件“个人所得税税率表及预扣率表”另附）
   - 中国政府网《国务院公报》2019 年第 12 号（含附件表格）：<https://www.gov.cn/gongbao/content/2019/content_5386991.htm>
   - 第八条原文要点：“劳务报酬所得……以收入减除费用后的余额为收入额”；“减除费用：预扣预缴税款时，劳务报酬所得……每次收入不超过四千元的，减除费用按八百元计算；每次收入四千元以上的，减除费用按收入的百分之二十计算”；“以每次收入额为预扣预缴应纳税所得额……劳务报酬所得适用个人所得税预扣率表二”。
   - 附件《个人所得税预扣率表二（居民个人劳务报酬所得预扣预缴适用）》：不超过 20000 元，20%，0；超过 20000 元至 50000 元的部分，30%，2000；超过 50000 元的部分，40%，7000。
   - 第十一条：劳务报酬所得属于一次性收入的，以取得该项收入为一次；属于同一项目连续性收入的，以一个月内取得的收入为一次。
   - 同一表格也见国家税务总局辽宁省税务局问答页（2023-07-07）：<https://liaoning.chinatax.gov.cn/art/2023/7/7/art_1920_105200.html>
2. **《中华人民共和国个人所得税法》**（2018-08-31 第七次修正），国家税务总局政策法规库：<https://fgk.chinatax.gov.cn/zcfgk/c100009/c5193028/content.html>
   - 第六条：劳务报酬所得以收入减除百分之二十的费用后的余额为收入额（年度汇算口径）；第十一条：有扣缴义务人的，由扣缴义务人按月或者按次预扣预缴税款，预扣预缴办法由国务院税务主管部门制定。
3. **《中华人民共和国个人所得税法实施条例》**（国务院令第 707 号），国家税务总局网站：<https://www.chinatax.gov.cn/n810219/n810744/n3752930/n3752974/c3963364/content.html>
   - 第六条第（二）项：劳务报酬所得的范围；第十四条：“每次”的确定方法，与公告第十一条一致。

**核实结论**
- “≤4000 减 800、>4000 减 20%”与公告一致。原文是“不超过四千元”和“四千元以上”，恰好 4000 元时两种算法都是 800 元，结果一样；工具按“≤4000 减 800”处理。
- 三档预扣率和速算扣除数与表二一致。表二写的是“不超过 20000 元”和“超过 20000 元至 50000 元的部分”，工具把 20000 和 50000 都算在较低一档（上限含本数）。经验算，边界两侧税额相等：20000×20% = 20000×30% − 2000 = 4000；50000×30% − 2000 = 50000×40% − 7000 = 13000。所以含不含本数不影响税额。
- 以上规则只用于**预扣预缴**；居民个人年度汇算时劳务报酬按“收入×80%”并入综合所得，多退少补，本工具不计算汇算。

## 4. 反算与校准规则

1. 正算对任意总成本都有确定结果，所以反算就是在总成本的分位网格上找“正算到手 = 目标”的总成本。按“是否征收 / 减除费用方式 / 预扣率档次”分段，每段内先二分、再按 0.01 上下逐分扫描校准。
2. 默认口径下**任意非负到手金额都能精确反算**，反算结果再正算回去完全一致：每个不含税收入都能由某个总成本精确拆分出来，而到手 = 收入 − 个税随收入每分最多变化 0.01。已用 0.01～200,000 元遍历、门槛前后逐分、总成本 0～70,000 元逐分暴力表验证。
3. **多解时取最小总成本**。门槛处存在多解：跳变段按征收处理时，总成本 1000.00 的到手（951.84）低于 999.99 的到手（959.99），所以到手 951.84～959.99 同时对应“不征收”（总成本 < 1000）和“跳变段征收”（1000.00～1010.29）两个总成本，默认取较小的不征收一侧，另一侧列为“其它可行总成本”。例如到手 959.99 → 总成本 999.99，另有 1010.29。
4. 到手与目标不一致只出现在自定义口径下（例如人为改了减除比例导致到手跳变），这时取最接近的总成本，标“不可精确达到”并给出差额。
5. 负数、超过两位小数的金额直接报错，不做静默舍入。
