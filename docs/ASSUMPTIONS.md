# 税务口径假设清单

本工具的所有口径都是 `config/default.toml` 中的配置项。下面列出默认值及依据：
- **【用户已确认】**：用户本人确认的口径（2026-10-21）；
- **【公开资料核实】**：已查到官方文本，出处见第 3 节；
- **【需确认】**：尚未确认，正式结算前请财务确认。

> 说明：本文档只陈述计算口径，不构成税务意见。

## 1. 计算流程（默认口径）

**核心变量是不含税收入 I**（未计增值税的劳务报酬收入，精确到分）。其它金额都由 I 唯一确定，不存在拆分误差，也没有跳变段的歧义。**【用户已确认】**

```
不含税收入 I（精确到分，I ≥ 0）
  ├─ 增值税 V = I ≥ 1000 ? round(I × 1%) : 0
  ├─ 附加税 S = round(V × 3%)
  ├─ 企业总成本 C = I + V + S（三项都由企业承担）
  ├─ 个税（居民个人劳务报酬预扣预缴，按 I）：
  │    减除费用 D = I ≤ 4000 ? 800（I < 800 时以 I 为限）: round(I × 20%)
  │    应纳税所得额 T = I − D
  │    代扣个税 P = round(T × 预扣率 − 速算扣除数)（预扣率表二）
  └─ 实际到手 = I − P（附加税不从到手扣）
```

round = 四舍五入到分（MidpointAwayFromZero），每一步单独舍入。

- **正算（主入口）**：输入不含税收入 I。CLI `labor-fee forward`、Web/API `/api/forward?net_income=`、库函数 `forward`。
- **反算**：输入实际到手，求出 I 再正算全部金额（见第 4 节）。
- **按企业总成本正算（辅助）**：输入总成本 C，内部求满足“正算总成本 = C”的 I；没有这样的 I 时报错，不倒挤、不输出差额（见第 5 节）。

## 3. 个税规则的公开出处（只列实际查到的内容）

1. **国家税务总局公告 2018 年第 61 号**《国家税务总局关于发布〈个人所得税扣缴申报管理办法（试行）〉的公告》，2018-12-21 发布，2019-01-01 起施行。
   - 国家税务总局网站：<https://www.chinatax.gov.cn/n810219/n810744/n3752930/n3752974/c3963396/content.html>（正文；附件“个人所得税税率表及预扣率表”另附）
   - 中国政府网《国务院公报》2019 年第 12 号（含附件表格）：<https://www.gov.cn/gongbao/content/2019/content_5386991.htm>
   - 第八条原文要点：“劳务报酬所得……以收入减除费用后的余额为收入额”；“减除费用：预扣预缴税款时，劳务报酬所得……每次收入不超过四千元的，减除费用按八百元计算；每次收入四千元以上的，减除费用按收入的百分之二十计算”；“以每次收入额为预扣预缴应纳税所得额……劳务报酬所得适用个人所得税预扣率表二”。
   - 附件《个人所得税预扣率表二（居民个人劳务报酬所得预扣预缴适用）》：不超过 20000 元，20%，0；超过 20000 元至 50000 元的部分，30%，2000；超过 50000 元的部分，40%，7000。
   - 第十一条：劳务报酬所得属于一次性收入的，以取得该项收入为一次；属于同一项目连续性收入的，以一个月内取得的收入为一次。
   - 同一表格也见国家税务总局辽宁省税务局问答页（2023-07-07）：<https://liaoning.chinatax.gov.cn/art/2023/7/7/art_1920_105200.html>
2. **《中华人民共和国个人所得税法》**（2018-08-31 第七次修正），国家税务总局政策法规库：<https://fgk.chinatax.gov.cn/zcfgk/c100009/c5193028/content.html>
   - 第六条：劳务报酬所得以收入减除百分之二十的费用后的余额为收入额（年度汇算口径）；第十一条：有扣缴义务人的，由扣缴义务人按月或者按次预扣预缴税款，预扣预缴办法由国务院税务主管部门制定。
3. **《中华人民共和国个人所得税法实施条例》**（国务院令第 707 号），国家税务总局网站：<https://www.chinatax.gov.cn/n810219/n810744/n3752930/n3752974/c3963364/content.html>
   - 第六条第（二）项：劳务报酬所得的范围；第十四条：“每次”的确定方法，与公告第十一条一致。

**核实结论**
- “≤4000 减 800、>4000 减 20%”与公告一致。原文是“不超过四千元”和“四千元以上”，恰好 4000 元时两种算法都是 800 元，结果一样；工具按“≤4000 减 800”处理。
- 三档预扣率和速算扣除数与表二一致。表二写的是“不超过 20000 元”和“超过 20000 元至 50000 元的部分”，工具把 20000 和 50000 都算在较低一档（上限含本数）。经验算，边界两侧税额相等：20000×20% = 20000×30% − 2000 = 4000；50000×30% − 2000 = 50000×40% − 7000 = 13000。所以含不含本数不影响税额。
- 以上规则只用于**预扣预缴**；居民个人年度汇算时劳务报酬按“收入×80%”并入综合所得，多退少补，本工具不计算汇算。

## 4. 反算与校准规则

1. 反算在不含税收入的分位网格上找“正算到手 = 目标”的 I：按“是否征收增值税 / 减除费用方式 / 预扣率档次”分段，每段内先二分、再按 0.01 上下逐分扫描校准，最后对选中的 I 正算全部金额。
2. **默认口径下到手随不含税收入单调不减，且收入每增加 0.01，到手只增加 0 或 0.01**（已对 I = 0～300,000 元逐分验证）。所以：
   - **不存在无解区间**：任意非负到手金额都能精确反算，反算结果再正算回去到分一致（0.01～200,000 元每隔 0.37 元遍历、各分段附近 ±10 元逐分、proptest 验证）。
   - **存在多解，但只是相邻几分的“平台”**：到手 = I − 个税，个税逐分舍入时会出现相邻的 I 得到同一到手（如到手 50000 对应 I = 63235.29 和 63235.30）。按规则取最小 I，结果中 `exact_net_income_range` 给出等效区间。默认口径下不存在不相连的多解（`other_solutions` 为空）。
   - 1000 门槛只改变增值税和附加税，不影响 I 和个税，所以**到手在门槛处是连续的**：到手 959.99 → I 999.99（总成本 999.99）；到手 960.00 → I 1000.00（总成本 1010.30）。
3. 无解（“不可精确达到”）和不相连的多解只会在自定义口径下出现，例如把 4000 元以上的减除比例改成 30%（到手向上跳，中间不可达）或 10%（到手向下跳，两段多解）。这两种情况都有测试：无解时取最接近的 I，标“不可精确达到”并给出差额；多解时取最小 I，其余列为“其它可行不含税收入”。
4. 负数、超过两位小数的金额直接报错，不做静默舍入。

## 5. 按企业总成本正算（辅助功能）

企业总成本 C 随不含税收入严格递增，但不是每个“分”都能取到：

| 空位类型 | 例子 | 原因 |
|---|---|---|
| 门槛空白区间 | 总成本 1000.00～1010.29（共 1030 个分） | 1000 元增值税征收门槛：I = 999.99 时不征收，总成本 999.99；I = 1000.00 时征收增值税 10.00、附加税 0.30，总成本 1010.30。 |
| 逐分舍入空位 | 总成本 1061.32 | 增值税、附加税逐分舍入：I = 1050.49 → 总成本 1061.31，I = 1050.50 → 1061.33（增值税从 10.50 变为 10.51）。不含税收入每增加 1 元，增值税约增加 0.01 元，总成本就跳过一个分；附加税同时进位时跳过两个分。默认口径下总成本 1010.30～70,000 元中约 69,000 处空位、共约 71,000 个分（约 1%）。 |

输入落在空位时**明确报错，不倒挤、不输出差额**，报错内容包括：原因（征收门槛 / 逐分舍入），以及两侧最近的有效总成本和各自对应的不含税收入。例如：

> 企业总成本 1005.00 没有对应的不含税收入：该总成本处于 1000 元增值税征收门槛形成的空白区间——不含税收入 999.99 对应总成本 999.99，1000.00 对应 1010.30，这一段没有对应的收入。两侧最近的有效总成本：999.99（不含税收入 999.99）、1010.30（不含税收入 1000.00）

> 企业总成本 1061.32 没有对应的不含税收入：原因是增值税、附加税逐分舍入——不含税收入 1050.49 对应总成本 1061.31，1050.50 对应 1061.33，中间的总成本取不到。两侧最近的有效总成本：1061.31（不含税收入 1050.49）、1061.33（不含税收入 1050.50）

CLI（`labor-fee from-cost`，`--json` 时输出 `gap` 结构，退出码 2）、Web 页面、API（`/api/from-cost` 返回 422，字段 `error`、`reason`、`gap`）和批量（输入列选“企业总成本”时，该行“校准状态”为“总成本不可达”，“备注”列写上述原因）都显示这段说明。**【用户已确认】**
