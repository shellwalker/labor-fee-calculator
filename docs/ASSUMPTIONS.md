# 税务口径假设清单

本工具不内置任何“地方性”或“时效性”政策判断，所有口径均为 `config/default.toml` 中的可配置项。
下表列出默认值及其依据；标注 **【需确认】** 的条目请业务/财务确认后再用于正式结算。

> 说明：本文档只陈述计算口径，不构成税务意见。

## 1. 计算流程（默认口径）

```
企业总成本 C
  ├─ 价税分离：不含税开票收入 N = round(C / (1 + 增值税征收率))；增值税 V = C − N
  ├─ 附加税   S = Σ round(V × 各税目税率)
  ├─ 个税收入额 X = N
  │    减除费用 D = X ≤ 4000 ? min(800, X) : round(X × 20%)
  │    应纳税所得额 T = X − D
  │    代扣个税 I = round(T × 预扣率 − 速算扣除数)
  └─ 实际到手 = N − S − I
```

## 2. 逐条假设

| 编号 | 配置项 | 默认值 | 说明 | 状态 |
|---|---|---|---|---|
| A1 | `cost.basis` | `vat_inclusive` | 企业总成本 = 价税合计 = 不含税收入 × (1 + 征收率)（增值税差额倒挤，保证 不含税收入 + 增值税 = 总成本）。可选 `vat_and_surcharge_inclusive`：总成本 = 不含税收入 + 增值税 + 附加税（不含税收入倒挤）。 | **【需确认】** 企业总成本是否包含附加税 |
| V1 | `vat.rate` | `0.01` | 增值税征收率按 1%（小规模纳税人/按次纳税的自然人，3% 减按 1%）。 | **【需确认】** 适用 3% 还是 1%、优惠是否仍在有效期、是否代开发票 |
| V2 | `vat.threshold_enabled` | `false` | 默认不考虑起征点。启用后以“每次计算的金额”判断，起征点金额由 `vat.threshold` 指定（按次/按月由使用方自行决定填什么）。 | **【需确认】** 是否适用起征点、按次还是按月、金额多少 |
| V3 | `vat.threshold_inclusive` | `false` | `false`：销售额 **<** 起征点免征（“未达到起征点”）；`true`：**≤** 起征点免征（如“月销售额 10 万元以下（含本数）”类表述）。 | **【需确认】** |
| V4 | （固定逻辑） | — | 起征点以 **总成本（免税时即销售额）** 判断：总成本未达起征点 → 免增值税且免附加税，不含税收入 = 总成本；否则全额计征。总成本刚超过起征点时价税分离后的不含税收入可能略低于起征点，仍按应税处理。 | **【需确认】** 判断基数 |
| S1 | `surcharge.items` | 单项“附加税” `0.03` | 按统筹方要求，默认用一个合计税率 3%。法定分项一般为：城市维护建设税 7%（市区）/5%（县城、镇）/1%（其他）、教育费附加 3%、地方教育附加 2%，可在配置中改为分项。 | **【需确认】** 3% 的含义（合计税率？已减半后的综合率？）以及纳税地 |
| S2 | `surcharge.base` | `vat` | 附加税以实际缴纳的增值税额为计税依据（法定口径）。可选 `net_revenue`：以不含税开票收入为基数。 | **【需确认】** |
| S3 | `surcharge.halve` | `false` | 是否对所有附加税目减半征收（小规模纳税人“六税两费”减征）。 | **【需确认】** |
| S4 | `rounding.surcharge` | `per_item` | 每个附加税目分别舍入到分后相加；可选 `total`（合计后一次舍入，明细末项倒挤）。 | **【需确认】** 税务系统实际舍入方式 |
| P1 | `iit.income_base` | `net_revenue` | 个税收入额基数 = 不含税收入（价税分离后计个税）。可选 `total_cost`。 | **【需确认】** |
| P2 | `iit.deduct_surcharge` | `false` | 计算个税收入额时不扣除附加税；可选扣除。 | **【需确认】** 附加税能否在劳务报酬收入中扣除 |
| P3 | `iit.fixed_deduction_limit` / `fixed_deduction` / `percent_deduction_rate` | 4000 / 800 / 20% | 劳务报酬预扣预缴：每次收入不超过 4000 元（含）减除 800 元（收入不足 800 时减除额以收入为限）；超过 4000 元减除 20%。 | 通用规则（已知） |
| P4 | `iit.brackets` | ≤20000：20%/0；20000–50000：30%/2000；>50000：40%/7000 | 劳务报酬所得预扣率表（按应纳税所得额，上限含本数）。 | 通用规则（已知） |
| P5 | （固定逻辑） | — | 按“每次收入”单次计算，不做同一项目连续性收入按月合并、不做年度汇算。 | **【需确认】** 同一人同月多次支付是否需合并为“一次” |
| T1 | `take_home.deduct_surcharge` | `true` | 实际到手 = 不含税收入 − 附加税 − 代扣个税（增值税、附加税由劳务方承担）。设为 `false` 则附加税由企业另行承担，不从到手中扣。 | **【需确认】** 税费由谁承担 |
| R1 | `rounding.scale` / `rounding.mode` | 2 / `half_up` | 每一步金额四舍五入到分（MidpointAwayFromZero）：价税分离的不含税收入、各附加税目、20% 减除费用、代扣个税均在该步舍入；增值税为差额不再舍入。 | **【需确认】** 与开票/申报系统的舍入是否一致 |
| R2 | `reverse.prefer` | `min_cost` | 反算存在多个总成本得到同一到手时（舍入造成的 1~2 分“平台”或起征点跳变导致的两段解），默认取最小企业总成本，其它分段解在结果中列出。 | **【需确认】** |
| R3 | `reverse.search_window` | 20 | 二分定位后前后各逐分扫描 20 分进行校准。 | 实现参数 |
| R4 | `reverse.max_cost` | 100 亿 | 反算搜索上限，超过报错“超出可计算范围”。 | 实现参数 |

## 3. 反算与校准规则

1. 到手金额关于总成本是分段函数。工具按“是否应税 / 减除费用方式 / 预扣率档次”自动求出分段点，在各分段内二分 + 逐分（0.01）扫描。
2. 若存在正算到手 **完全等于** 目标（到分）的总成本：结果标记“精确”，按 `reverse.prefer` 取值，并给出等效总成本区间与其它分段的解。
3. 若因舍入或跳变不存在精确解：取正算到手与目标差额绝对值最小的总成本（同差额取较小者），标记“不可精确达到”，并给出 差额 = 正算到手 − 目标。
4. 负数、超过配置精度（默认 2 位小数）的金额直接报错，不做静默舍入。
5. 默认口径下，经测试 0.01 ~ 200,000 元范围内的所有到手金额均可精确达到（逐分步长下到手每次最多变化 0.01）。

## 4. 批量反算的输入输出约定

| 编号 | 约定 | 状态 |
|---|---|---|
| B1 | 只处理第一个工作表；首行是标题行；列标题默认“到手金额”（精确匹配，可在 CLI `--column`/Web 表单中修改）。 | **【需确认】** 模板格式 |
| B2 | Excel 数值单元格本身是浮点数：读入时转十进制，允许 1e-6 以内的浮点噪声后舍入到分，否则视为超过两位小数报错；写出 xlsx 时金额以数值单元格（格式 0.00）写入。计算过程全程十进制。 | 实现约定 |
| B3 | 输出为新文件，只保留原单元格的值，不保留原格式、公式、合并单元格及其它工作表。 | **【需确认】** 是否需要保留原格式 |
| B4 | 每行按“一次”劳务报酬独立反算，不按同一人合并。 | **【需确认】**（同 P5） |
