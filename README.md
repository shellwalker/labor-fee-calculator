# 劳务报酬计算工具（labor-fee-calculator）

计算劳务报酬涉及的 **增值税及附加税费（企业承担）、个人所得税（居民个人劳务报酬所得预扣预缴）**，支持：

- **按不含增值税收入计算（主入口）**：不含增值税收入 → 增值税税额、增值税附加税费（城市维护建设税 / 教育费附加 / 地方教育附加，可分别设置是否征收，可享受减征优惠，列示减征前后金额）、企业总支出、个人所得税（每次收入、减除费用、预扣预缴应纳税所得额、预扣率、速算扣除数、应预扣预缴税额）、税后实发金额；
- **按税后实发金额测算**：税后实发金额 → 不含增值税收入 → 上述全部金额，再计算回去与目标到分一致（精确匹配），多解取最小不含增值税收入；
- **按企业总支出测算**：求对应的不含增值税收入；企业总支出不可达（增值税起征点形成的不可达区间、按分舍入形成的不可达金额）时报错，说明原因并给出两侧最近的有效企业总支出；
- **批量测算**：读取 xlsx/xls/ods/csv 首行标题为“税后实发金额”的列（兼容旧列名“实发金额”“到手金额”；也可选“不含增值税收入”“企业总支出”列），在右侧追加结果列并输出新文件；
- **三种使用方式**：原生桌面程序 `labor-fee-desktop`（Windows / macOS / Linux）、命令行 `labor-fee`、简易 Web 页面 `labor-fee-web`。

金额全部使用 `rust_decimal` 十进制运算，不使用浮点数。全部计算参数与舍入规则均可配置；默认参数、政策出处及待确认事项见 [docs/ASSUMPTIONS.md](docs/ASSUMPTIONS.md)，界面用语与官方依据见 [docs/TERMINOLOGY.md](docs/TERMINOLOGY.md)。

## 默认计算参数（用户已确认）

- 以**不含增值税收入 I** 为核心变量，其余金额都由它唯一确定；
- **增值税税额** = round(I × 1%)：小规模纳税人 3% 征收率减按 **1% 优惠征收率**（财政部 税务总局公告2026年第10号，可在设置中改为 3% 等）；
- **增值税起征点**：不含增值税收入达到 1000 元（含本数）的征收增值税及附加税费，未达到的两者均为 0（与按次纳税起征点“每次（日）销售额1000元”一致；个人所得税不受影响）；
- **增值税附加税费** = 各征收项目 round(增值税税额 × 法定费率 × (1 − 减征比例)) 之和，**三项默认均征收**（用户已确认）：城市维护建设税按纳税人所在地分档（市区 7% / 县城、镇 5% / 其他 1%，各档税率可修改，默认档位“不在市区、县城或者镇”1%）、教育费附加 3%、地方教育附加 2%，默认合计比例 6%；不征收的项目在设置中“是否征收”选“否”；
- **附加税费减征优惠**：默认享受，减征比例 50%（财政部 税务总局公告2023年第12号第二条：增值税小规模纳税人 2023-01-01 至 2027-12-31 减半征收城市维护建设税、教育费附加、地方教育附加；国家税务总局问答明确自然人按小规模纳税人享受，代开发票时适用）。默认合计比例 6% → 3%：10000 元时城市维护建设税 0.50 + 教育费附加 1.50 + 地方教育附加 1.00 = 3.00（减征前 6.00）。可在设置中关闭或改比例；
- **企业总支出** = I + 增值税税额 + 增值税附加税费，三项都由企业承担；
- 个人所得税：居民个人劳务报酬所得预扣预缴（国家税务总局公告2018年第61号），每次收入不超过 4000 元减除费用 800 元、4000 元以上减除 20%，预扣率表二 20%/0、30%/2000、40%/7000；
- **税后实发金额** = 不含增值税收入 − 应预扣预缴税额。

```
docs/ASSUMPTIONS.md   计算参数假设与待确认清单

```

## 构建

需要 Rust 1.85+。

```bash
cargo build --release
# 可执行文件：target/release/labor-fee、target/release/labor-fee-web
```

## 用法

```bash
# 按不含增值税收入计算（主入口）：不含增值税收入 10000 元
labor-fee forward 10000

# 按税后实发金额测算：税后实发 8400 元
labor-fee reverse 8400

# 按企业总支出测算
labor-fee from-cost 10103.00
labor-fee from-cost 1005      # 位于起征点形成的不可达区间：报错并给出原因和两侧最近的有效企业总支出

# JSON 输出
labor-fee reverse 8400 --json

# 使用自定义参数
labor-fee config > my.toml        # 导出当前配置后修改
labor-fee -c my.toml forward 10000

# 批量测算（输出 sample_测算结果.csv；xlsx/xls/ods 输入则输出 xlsx）
labor-fee batch examples/sample.csv
labor-fee batch 名单.xlsx -o 结果.xlsx --column 到手金额   # 旧列名同样可用
# 按不含增值税收入 / 企业总支出批量（输出 原名_计算结果）
labor-fee batch 名单.xlsx --input-kind net-income      # 读“不含增值税收入”（或“不含税收入”）列
labor-fee batch 名单.xlsx --input-kind total-cost      # 读“企业总支出”（或“企业总成本”）列
```

按税后实发金额测算示例（默认参数，附加税费为减半后的金额，城建 + 教育 + 地方教育）：

| 税后实发金额 | 不含增值税收入 | 增值税税额 | 增值税附加税费 | 企业总支出 | 应预扣预缴税额 |
|---|---|---|---|---|---|
| 959.99 | 999.99 | 0.00 | 0.00 | 999.99 | 40.00 |
| 960.00 | 1000.00 | 10.00 | 0.05 + 0.15 + 0.10 = 0.30 | 1010.30 | 40.00 |
| 3360 | 4000.00 | 40.00 | 0.20 + 0.60 + 0.40 = 1.20 | 4041.20 | 640.00 |
| 20000 | 23809.52 | 238.10 | 1.19 + 3.57 + 2.38 = 7.14 | 24054.76 | 3809.52 |
| 50000 | 63235.29 | 632.35 | 3.16 + 9.49 + 6.32 = 18.97 | 63886.61 | 13235.29 |

税后实发金额随不含增值税收入单调不减、每分最多变化 0.01，所以任意金额都能精确匹配；起征点只影响增值税及附加税费，税后实发金额在 1000 元处连续。

按企业总支出测算时，1000.00～1010.29 是增值税起征点形成的不可达区间（不含增值税收入 999.99 对应 999.99，1000.00 对应 1010.30；区间随附加税费配置变化，不享受减征时为 1000.00～1010.59，仅征收教育费附加并减半时为 1000.00～1010.14）；增值税税额及附加税费按分舍入还会留下单个不可达金额（如 1061.32：1050.49 → 1061.31，1050.50 → 1061.33）。附加税费默认各项分别按分舍入（`per_item`），小金额时各项舍入之和可能与合计后舍入（`total`）相差 1 分；例如不含增值税收入 1030.00（增值税 10.30）：逐项 0.05 + 0.15 + 0.10 = 0.30，合计后舍入 10.30 × 3% = 0.309 → 0.31。输入不可达时报错，例如：

```
错误：企业总支出 1005.00 无对应的不含增值税收入：该金额位于增值税起征点（1000 元）形成的不可达区间。不含增值税收入 999.99 对应企业总支出 999.99，1000.00 对应 1010.30，其间的企业总支出均无对应收入。两侧最近的有效企业总支出：999.99（不含增值税收入 999.99）、1010.30（不含增值税收入 1000.00）
```

## 批量测算说明

- 只读第一个工作表；首行为标题行，按标题精确匹配（忽略首尾空格）。默认读“税后实发金额”列（依次尝试“税后实发金额”“实发金额”“到手金额”）；`--input-kind net-income`/`total-cost` 改读“不含增值税收入”（或“不含税收入”）/“企业总支出”（或“企业总成本”）列，`--column` 可指定其他标题。
- 金额单元格可为数值或文本，文本允许 `¥`、`元`、千分位逗号；超过两位小数、无法解析的行“测算状态”写“数据错误”，“备注”写原因；企业总支出不可达的行“测算状态”写“总支出不可达”，“备注”写原因和两侧最近的有效企业总支出。出错行不中断其他行。空白行保留原样、结果列为空。
- 追加列：不含增值税收入、增值税税额、各征收的附加税费项目（减征后实际金额，默认城市维护建设税、教育费附加、地方教育附加三列）、附加税费减征额、增值税附加税费合计、企业总支出、每次收入、减除费用、预扣预缴应纳税所得额、预扣率、速算扣除数、应预扣预缴税额、税后实发金额、测算状态（精确匹配 / 无法精确匹配，差额 x / 已计算 / 数据错误 / 总支出不可达）、差额、备注。
- CSV 输入自动识别 UTF-8（含 BOM）/GBK，输出 UTF-8 带 BOM（Excel 可直接打开）。表格输出为新的 xlsx，只保留原单元格的值，不保留原格式、公式与其他工作表。

## Web 页面

```bash
labor-fee-web --listen 127.0.0.1:8080 [-c my.toml] [--max-upload-mb 20]
```

浏览器打开 `http://127.0.0.1:8080`：单笔按不含增值税收入计算 / 按税后实发金额测算 / 按企业总支出测算、上传表格批量测算并自动下载结果、查看当前计算参数。接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/forward?net_income=10000` | 按不含增值税收入计算（主入口），返回 JSON |
| GET | `/api/reverse?take_home=8400` | 按税后实发金额测算，返回 JSON（含 `exact`、`diff`、`exact_net_income_range`、`other_solutions`） |
| GET | `/api/from-cost?total_cost=10103.00` | 按企业总支出测算；不可达时返回 422，`error` 为原因说明，`gap` 含 `reason`（`threshold`/`rounding`）和两侧最近的有效企业总支出 `lower`/`upper` |
| POST | `/api/batch` | multipart 字段 `file`（必填）、`input_kind`（`take-home` 默认/`net-income`/`total-cost`）、`column`（可选），返回结果文件；响应头 `x-batch-summary` 为统计 |
| GET | `/api/config` | 当前配置（TOML） |

服务没有登录鉴权，默认只监听本机；如需对外提供请放在带鉴权的反向代理之后。

## 桌面程序

`labor-fee-desktop` 是单个可执行文件，计算全部复用 `crates/core` 与 `crates/batch`。

```bash
labor-fee-desktop                   # 使用“设置”中保存的计算参数（未保存过则为内置默认参数）
labor-fee-desktop --config my.toml  # 本次运行临时使用参数文件（不写入设置）
labor-fee-desktop --version         # 版本、git 短哈希、构建日期
```

界面设计说明见 [docs/UI_DESIGN.md](docs/UI_DESIGN.md)。默认浅色/深色**跟随系统**，可在设置中改为固定浅色或深色（顶栏的主题按钮也可快速切换），选择会被记住。

窗口结构：顶部品牌栏（图标、应用名、导航“收入计算 / 实发测算 / 支出测算 / 批量测算”、计算参数徽章（窗口较窄时隐藏）、主题切换、设置），页面标题显示完整名称（按不含增值税收入计算 / 按税后实发金额测算 / 按企业总支出测算 / 批量测算），底部状态栏（计算参数是否为内置默认参数、版本与构建信息）。Windows / Linux 在窗口顶部有菜单栏；macOS 使用系统原生应用菜单。

| 页面 | 内容 |
|---|---|
| 收入计算 / 实发测算 / 支出测算 | 左：输入卡片（大号输入框、单位“元”、回车或“计算”、快捷示例金额）与最近记录；中：按页区分的 KPI 指标卡（用户输入项不做卡片；收入计算为增值税税额 / 附加税费合计 / 企业总支出 / 应预扣预缴税额 / 税后实发金额；实发测算、支出测算相应替换输入项为测算所得；宽屏一行或 3+2，窄屏自适应）、校验状态徽章、“增值税及附加税费”（逐项列出征收的附加税费，享受减征时注明法定费率、减征比例及减征前金额、减征额，另列附加税费减征额与合计）和“个人所得税”两组明细（千分位、等宽右对齐）、算式核对；右：**计算规则**面板（按当前参数动态生成：征收率与起征点、各项附加税费（含减征算式）及合计、附加税费合计比例（减征前后）、不征收项目、企业承担、减除费用规则、预扣率表、逐步舍入、测算取最小解、不可达区间，并附政策依据链接），可收起 |
| 支出测算（不可达时） | 红色警示卡：原因、数轴示意（两侧有效值与不可达区间）、两侧最近的有效企业总支出按钮（点击即填入并重新测算） |
| 批量测算 | 四步：① 拖放或选择文件 ② 选择输入列（税后实发金额 / 不含增值税收入 / 企业总支出）和列标题 ③ 执行 ④ 导出（保存到输入文件旁 / 另存为）；彩色统计卡片（总行数、成功、无法精确匹配/不可达、错误、空白）；预览表（表头固定、斑马纹、数字右对齐、错误行红底、可横向滚动、可调列宽） |

窗口宽度 ≥ 1120 时三栏，820～1120 时两栏（计算规则移到输入下方），更窄时单列滚动；最小窗口 960×640。

### 设置

“设置”对话框左侧为分组导航，按业务性质分为三组：

| 分组 | 页 | 内容 |
|---|---|---|
| 计税口径 | 增值税 | 征收率（当前按 1% 优惠征收率，可改为 3% 等）；起征点：是否启用、金额、恰好等于起征点时是否征收 |
| | 附加税费 | 顶部“附加税费合计比例”卡片（减征前 → 减征后合计比例，及各项目法定费率 / 减征 / 实际征收率；有未生效修改时附预览）；减征优惠（是否享受，单选“否 / 是”，选“是”后显示减征比例，小字注明政策来源并附链接）；城市维护建设税 / 教育费附加 / 地方教育附加各自的“是否征收”（单选，“否”在前，三项默认“是”；选“否”隐藏具体配置，选“是”展开：城市维护建设税选择纳税人所在地，每档右侧可修改该档税率——市区 7% / 县城、镇 5% / 其他 1%，默认选中 1% 档；另两项填写征收比例）；可添加其他项目；计税依据 |
| | 个人所得税 | 定额减除上限与金额、定率减除比例；预扣率表各档（可增删，最后一档无上限）；适用范围说明 |
| 计算规则 | 金额舍入 | 小数位、舍入方式、附加税费舍入方式 |
| | 测算求解 | 按税后实发金额测算（含批量）时的多解取值、逐分校准窗口、测算搜索上限 |
| 通用 | 外观 | 主题（跟随系统 / 浅色 / 深色） |
| | 设置存储 | 设置文件的保存位置说明 |

页名右侧的小圆点提示该页有“已修改”（红）或“未生效”（橙）的项目，有错误时显示错误数。

- **逐项确认**：修改任一项后，该项进入“未生效”状态（控件橙色描边、“未生效”标签），行内出现 ✔（生效）和 ✖（放弃本项修改）。点击 ✔ 或按 Enter 后立即生效（主界面已有结果按新参数重新计算）并写入设置文件；点击 ✖ 或按 Esc 恢复为当前生效值。输入非法时 ✔ 不可用，并在该项下方说明原因。预扣率表整张作为一项确认；新增的附加税费项目填写后点击 ✔ 生效。
- **与默认值不同的提示**：生效值与内置默认不同时，该项显示 **已修改** 标签，并在补充说明区常驻一行“当前值与默认值不同（默认：…）”；底部显示“与内置默认不同 N 项”（与“已修改”标签逐项一致）。其他项标注 **已确认 / 已核实 / 待确认 / 实现参数**。
- **单选切换同样逐项确认**：附加税费页的“是否征收”“享受减征优惠”“纳税人所在地”等单选切换后，该项进入“未生效”状态并显示 ✔ ✖，选“是”时展开的内容预填该项已保存的费率（未修改过即法定标准）；点击 ✔ 才生效并写入设置文件。从“是”改回“否”时，隐藏的费率恢复为生效值，不会留下看不见的修改。
- **单项“默认”**：**不弹框**，只把该项的输入填为内置默认值并进入“未生效”状态，右侧出现 ✔ ✖；点击 ✔ 才生效并保存，点击 ✖ 放弃（生效值已等于默认时不显示“默认”按钮）。删除已生效的自定义附加税费项目立即生效。
- **全部恢复默认**（窗口左下角）：二次确认后，将全部计算参数和外观偏好恢复为内置默认并立即生效，`rules.toml` 删除、`preferences.toml` 还原为默认。
- 由于每项确认后即保存，窗口底部只有“关闭”。存在未生效的修改时关闭窗口（“关闭”、Esc、`⌘W` / `Ctrl+W` 或点击窗口外），会询问“放弃未生效的修改 / 返回”。
- 设置保存在平台标准配置目录的 `labor-fee-desktop/` 下：Linux `~/.config/`（遵循 `$XDG_CONFIG_HOME`）、macOS `~/Library/Application Support/`、Windows `%APPDATA%\`。`preferences.toml` 存主题，`rules.toml` 存计算参数（与内置默认参数相同时不保存），由程序自动维护。旧版只有单一“附加税”项目的配置读入时视为教育费附加；旧版 `halve = true / false` 读入时映射为享受减征 50% / 不享受减征。

测试表格：[samples/到手样例.xlsx](samples/到手样例.xlsx)（列名为旧名“到手金额”：500、959.99、960、3360、20000、50000 和一个非法值）。

### 构建

各平台在本机独立编译，产物都输出到 `dist/`。不需要 GitLab 流水线。桌面程序需要 Rust 1.95 及以上（eframe 0.37 的要求）。

| 平台 | 命令 | 构建依赖 | 产物 |
|---|---|---|---|
| Linux | `scripts/build-linux.sh` | `build-essential pkg-config libgtk-3-dev`（Debian/Ubuntu），或 `gcc pkgconf-pkg-config gtk3-devel`（Fedora） | `dist/linux-<arch>/labor-fee-desktop` 等，以及 `.tar.gz` |
| macOS | `scripts/build-macos.sh` | Xcode Command Line Tools（`xcode-select --install`） | `dist/macos-arm64/LaborFee.app`（仅 Apple Silicon / M 系列），以及 `labor-fee-<版本>-macos-arm64.zip` |
| Windows | `powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1` | Visual Studio 生成工具（C++ 桌面开发，MSVC） | `dist\windows-x86_64\labor-fee-desktop.exe` 等，以及 `.zip` |
| 交叉构建（可选） | `scripts/cross-build-docker.sh linux\|windows\|macos\|all` | Docker 或 Podman；加 `--no-docker` 则在本机执行，例如本机装 mingw-w64 后构建 Windows 版 | `dist/linux-x86_64/`、`dist/windows-gnu-x86_64/`、`dist/macos-arm64/` |

说明：

- **Linux**：
  - 文件对话框默认用 GTK3 后端，不依赖 xdg-desktop-portal。可加 `--features portal` 改用 portal，这样不依赖 GTK。
  - 渲染用 OpenGL（glow），虚拟机和远程桌面也能运行。
  - 运行时需要 `libgl1`（Mesa）、`libxkbcommon0`，X11 下还需要 `libxkbcommon-x11-0`，GTK3 后端另需 `libgtk-3-0`。
  - 其它参数：`--target aarch64-unknown-linux-gnu`、`--desktop-only`。
- **macOS**：
  - 只构建 Apple Silicon（M 系列，`aarch64-apple-darwin`）版本，最低 macOS 11.0；不提供 Intel / universal 版本。
  - 在 Intel Mac 上也能运行脚本，会交叉编译出 arm64 版本（自动 `rustup target add`），但产物只能在 M 系列 Mac 上运行。
  - 其它参数：`--desktop-only`。
  - 默认对 .app 做 ad-hoc 签名，`--no-sign` 可跳过。
  - 程序没有经过公证，首次打开需要右键“打开”，或在“隐私与安全性”中允许。
- **Windows**：
  - 发布构建的桌面程序是 Windows GUI 子系统程序（源码里设置了 `windows_subsystem = "windows"`），双击运行不会弹出控制台窗口。
  - 可用 `-Target aarch64-pc-windows-msvc` 或 `-DesktopOnly`。
- **交叉构建**：
  - Windows 目标为 `x86_64-pc-windows-gnu`（mingw-w64），产物只依赖系统 DLL。
  - macOS 只构建 `aarch64-apple-darwin`，使用 osxcross，需要用 `--macos-sdk <MacOSX*.sdk.tar.xz>` 自备 SDK（请自行确认 Apple SDK 的许可条款）；不提供 SDK 时跳过 macOS。装有 [rcodesign](https://github.com/indygreg/apple-platform-rs) 时自动 ad-hoc 签名，否则需在 Mac 上执行 `codesign --force --deep -s - LaborFee.app`。

## 配置说明

配置为 TOML，金额与比率请写成字符串（如 `"0.01"`）以保证精确。主要项：

| 段 | 关键项 | 含义 |
|---|---|---|
| `[rounding]` | `scale`、`mode`、`surcharge` | 小数位；舍入方式 `half_up`/`half_even`/`down`/`up`；附加税费逐项（`per_item`）或合计（`total`）舍入 |
| `[vat]` | `rate`、`threshold_enabled`、`threshold`、`levy_at_threshold` | 征收率；按不含增值税收入判断的起征点、恰好等于起征点时是否征收 |
| `[surcharge]` | `base`、`relief_enabled`、`relief_rate`、`[surcharge.urban_construction]`、`[[surcharge.items]]` | 计税依据（实际缴纳的增值税税额 / 不含增值税收入）；是否享受减征优惠、减征比例（0～1，默认 `true`、`"0.5"`，统一适用于全部征收项目）；城市维护建设税档位（`region` = `urban` / `county_town` / `other`，默认 `other`；各档税率 `urban` / `county_town` / `other`，默认 `"0.07"` / `"0.05"` / `"0.01"`，须在 0～1 之间；写明 `region` 时城建项目税率取该档税率）；附加税费项目（`name`、`rate` 为法定费率、`enabled`，默认三项均为 `true`；`enabled = false` 的项目不征收） |
| `[iit]` | 减除费用参数、`[[iit.brackets]]` | 减除费用与预扣率表（按不含增值税收入计算） |
| `[reverse]` | `prefer`、`search_window`、`max_net_income` | 多解取值、校准窗口、不含增值税收入搜索上限 |

纳税人所在地在市区的示例（城市维护建设税 7% + 教育费附加 3% + 地方教育附加 2%，减半征收后合计比例 6%；默认配置中只需把 `region` 改为 `"urban"`）：

```toml
[surcharge]
base = "vat"
relief_enabled = true
relief_rate = "0.5"

[surcharge.urban_construction]
region = "urban"
urban = "0.07"
county_town = "0.05"
other = "0.01"

[[surcharge.items]]
name = "城市维护建设税"
rate = "0.07"
enabled = true

[[surcharge.items]]
name = "教育费附加"
rate = "0.03"
enabled = true

[[surcharge.items]]
name = "地方教育附加"
rate = "0.02"
enabled = true
```

旧版写法单一 `rate` 或单一“附加税”项目（视为教育费附加，另两项按新默认补齐为征收）仍可读取；旧配置中明确写了 `enabled = false` 的项目保持不征收，未写 `enabled` 的视为征收。未写 `[surcharge.urban_construction]`（或未写 `region`）时按城市维护建设税项目税率匹配档位，已写 7% / 5% 的保持原值。旧版 `halve = true` 视为 `relief_enabled = true, relief_rate = "0.5"`，`halve = false` 视为 `relief_enabled = false`；与 `relief_*` 同时出现时以 `relief_*` 为准；均未写时取默认（享受、50%）。重新保存只写 `relief_*`。

## 作为库使用

```rust
use labor_fee_core::{forward, from_total_cost, CalcError, Config, Reverser};
use rust_decimal_macros::dec;

let cfg = Config::default();
let b = forward(&cfg, dec!(10000))?;     // 不含增值税收入 → 全部金额
assert_eq!(b.total_cost, dec!(10103.00));
assert!(matches!(from_total_cost(&cfg, dec!(1005)), Err(CalcError::CostUnreachable(_))));
let rev = Reverser::new(&cfg)?;          // 批量测算时复用
let r = rev.reverse(dec!(8400))?;
assert!(r.exact && r.breakdown.take_home == dec!(8400));
```
